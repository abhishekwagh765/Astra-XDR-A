Capabilities

What ASTRA-XDR
actually watches.

Every capability below is live on the dashboard right now — pulled straight from the Kubernetes API, the metrics-server, and Falco's runtime events.

Cluster Overview

Live counts of nodes, namespaces, pods, and services, read directly from the Kubernetes API via the astra-sa service account.

Pod Risk Scoring

Every pod is classified LOW, MEDIUM, HIGH, or CRITICAL based on its phase — Running, Pending, Failed, or an unexpected state — with a plain-language reason attached.

Live Falco Alert Feed

Falco posts runtime security events straight to /api/falco/events. The dashboard renders each one with its rule, priority, namespace, pod, container, and raw output.

Node & Pod Metrics

CPU (millicores) and memory (MiB) for every node and pod, sourced from the metrics.k8s.io API and refreshed automatically.

Top CPU & Memory Pods

Pods are automatically ranked by resource consumption, so the noisiest — or most suspicious — workloads surface immediately.

Real-Time Auto-Refresh

The dashboard polls cluster state, metrics, and Falco events on a short interval, so what you're looking at stays current without a manual reload.

Security-Gated CI/CD

Every push runs through SonarCloud SAST and a Trivy container scan — builds with critical or high vulnerabilities are blocked before they ever reach the cluster.

Least-Privilege RBAC

The astra-role ClusterRole grants only read access (get/list/watch) to the exact resources the platform needs — no write access to your cluster.

Kubernetes-Native Health Checks

A dedicated /health endpoint backs the Deployment's liveness and readiness probes, so Kubernetes manages the platform's own availability.
