CI/CD Pipeline

The exact 4 stages defined in ci.yml

On every push and pull request to main, GitHub Actions runs this pipeline end to end — each stage gated on the one before it.

1. SAST Scan

SonarCloud scans the codebase for code quality and security issues before anything is built.

2. Build & Trivy Scan

The Docker image is built and scanned by Trivy; the pipeline fails on any CRITICAL or HIGH vulnerability.

3. Push to Docker Hub

A passing image is tagged and pushed to mrrobot7781/astra-xdr:latest.

4. Deploy to Kubernetes

kubectl apply -f k8s/, then a rollout restart of deployment/astra-xdr in the astra namespace — verified before the run completes.

Security gates, not afterthoughts

Both the SonarCloud and Trivy stages can hard-fail the pipeline. A vulnerable or low-quality build never reaches Docker Hub, let alone the cluster.

Verified rollout

The deploy stage waits on kubectl rollout status with a timeout, then confirms pods and services are healthy in the astra namespace.
